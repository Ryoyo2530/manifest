# 1. Product Vision

## 1.1 What is Manifest?

Manifest is an AI-powered Personal Manifestation Space that transforms people's wishes and aspirations into personalized visual and audio experiences.

Users describe the life they want to experience. Manifest uses AI to turn those wishes into personalized manifestation content — short videos, images, and audio — allowing users to visualize, feel, and emotionally connect with their desired future.

**Core positioning:**

> Your dreams, brought to life.  
> A personal space to visualize the life you wish to create.

Manifest is not primarily an AI content-generation tool. It is an emotional experience product.

The product aims to provide:

- **Emotional Value:** Help users feel hopeful, inspired, confident, loved, abundant, and connected to their aspirations.
- **Visualization:** Turn abstract wishes into vivid, personalized experiences.
- **Personal Connection:** Create content that feels like it belongs to the individual user, rather than generic motivational content.
- **Ritual & Continuity:** Give users a space to revisit their wishes and reconnect with the feelings they want to cultivate.

Manifest should feel like a personal sanctuary for one's dreams, rather than a conventional SaaS dashboard.

## 1.2 Product Principles

1. **Wish First:** The user's wish is the central business object and starting point of the experience.
2. **Personalization First:** Content should be generated specifically for the user's wish, not simply selected from a predefined content library.
3. **Emotion Over Technology:** Users should feel the experience, not think about AI models, prompts, or generation workflows.
4. **Beautiful by Default:** Every generated result should feel visually intentional and emotionally engaging.
5. **Low Friction:** Creating a wish and generating content should be straightforward.
6. **Responsible Manifestation:** Encourage positive visualization, reflection, and motivation without promising supernatural outcomes or guaranteed real-world results.

# 2. MVP Objectives

The MVP should validate three core hypotheses:

**H1 — Users want to visualize their personal wishes.**

Users are willing to describe their aspirations and turn them into personalized content.

**H2 — Personalized manifestation content provides emotional value.**

Users find the generated content meaningful enough to revisit, save, regenerate, or share.

**H3 — Users are willing to return to their Personal Manifestation Space.**

Users develop a habit of revisiting their wishes and engaging with their manifestation content.

## 2.1 Primary Success Metrics

| Metric | What it measures |
|---|---|
| Wish Creation Rate | Percentage of registered users who create at least one wish |
| Generation Completion Rate | Percentage of generation requests that successfully produce content |
| First Result Engagement | Whether users view, save, or interact with their first result |
| Regeneration Rate | Whether users want to improve or explore alternative visualizations |
| 7-Day Return Rate | Whether users return to their manifestation space |
| Share Rate | Whether users share their generated content |

The first MVP should prioritize successful wish creation, generation quality, and first-result engagement over complicated retention mechanisms.

# 5. Core User Journey

The most important user journey is:

**Landing Page → Create Wish → Personalization → Generate → Experience → Save / Share → Return to My Manifest**

Detailed flow:

1. User enters Manifest.
2. User clicks "Create Your Wish".
3. User describes what they want to manifest.
4. User optionally provides additional personalization details.
5. AI interprets the wish and creates a manifestation concept.
6. User chooses the output format: Video, Image, or Audio.
7. User starts generation.
8. System displays an immersive generation experience.
9. User receives their personalized result.
10. Result is automatically associated with the original wish.
11. User can save, download, share, or regenerate.
12. User can revisit the result anytime in My Manifest.

The key design decision:

**Creating a Wish should lead directly into the generation experience.**

The user should not have to create a wish and then manually search a content library for something relevant.

## 6.3 AI Generation Flow

**Priority: P0 — Main Product Differentiator**

This is the most important feature of Manifest.

### A. Generation Entry

Generation starts immediately after wish creation.

The user should not need to understand technical generation parameters.

### B. Personalization Inputs

The initial generation flow should collect enough information to make the result feel personal without overwhelming the user.

Required:
- Wish description

Optional:
- Preferred visual style
- Mood / emotional atmosphere
- Whether the content should feature the user
- Additional details

Potential personalization dimensions:

| Dimension | Examples |
|---|---|
| Visual Style | Cinematic, Dreamy, Luxury, Romantic, Ethereal |
| Mood | Peaceful, Confident, Excited, Loved, Abundant |
| Personal Presence | First-person POV, Self-representation, Environment only |
| Details | Location, lifestyle, clothing, environment, relationship context |

For MVP, do not expose too many technical settings.

A simple guided interface is preferred over a complicated configuration panel.

**Important:** If the user chooses self-representation, the system may need a reference photo. This should be optional and accompanied by clear consent and privacy information. The user must be able to generate content without uploading a personal photo.

### C. Output Formats

MVP supports three content formats:

| Format | Requirement | Maximum Duration |
|---|---|---|
| Video | Personalized manifestation video | 30 seconds |
| Image | Personalized manifestation image | N/A |
| Audio | Personalized affirmation / manifestation audio | 30 seconds |

Recommended output specifications:

**Video**
- MP4
- H.264
- 9:16 as the default social-friendly aspect ratio
- 1080 × 1920 target resolution
- Up to 30 seconds

**Image**
- JPG or WebP
- High-resolution output
- 9:16 or 1:1 aspect ratio

**Audio**
- MP3
- Up to 30 seconds
- Personalized affirmation, visualization narration, or ambient experience

The 30-second limit applies to the final user-facing asset, not necessarily the internal AI generation process.

### D. Generation Concept

Before generation, AI should interpret the wish and transform it into a creative concept.

Example:

Wish:
"I want to become financially free and live a luxurious life."

Possible creative interpretation:
- Visual scene: A beautiful penthouse overlooking a modern city.
- Atmosphere: Golden sunlight, elegant interiors, warm champagne tones.
- Emotional tone: Confidence, abundance, freedom.
- Affirmation: "I am creating a life of abundance, freedom, and endless possibilities."

The concept should guide the generation process.

The system should avoid producing generic results that merely repeat the wish text.

### E. Generation Pipeline

Internal workflow:

1. Receive Wish and personalization inputs.
2. AI analyzes intent and extracts relevant concepts.
3. Generate a creative brief.
4. Generate personalized image / video / audio.
5. Generate or select a matching affirmation when appropriate.
6. Compose final media.
7. Run quality checks.
8. Upload final asset to storage.
9. Save metadata and associate the result with the Wish.
10. Return the completed result to the user.

The user should only see a simple generation experience.

### F. Generation Status

Each generation request should support:

- Pending
- Processing
- Completed
- Failed

The frontend should display meaningful feedback during generation.

Example generation messages:

- "Your wish is taking shape..."
- "Creating your personal manifestation..."
- "Bringing your vision to life..."
- "Almost ready..."

Avoid misleading users with fake progress percentages when the backend cannot provide real progress.

### G. Result Page

After successful generation, display the result prominently.

Available actions:

- Play / View
- Download
- Save to Favorites
- Share
- Regenerate
- Return to Wish

For video and audio, provide appropriate playback controls.

For images, provide a full-size viewing experience.

A short affirmation can accompany the result.

The experience should feel rewarding and emotionally satisfying.

### H. Regeneration

Users should be able to generate alternative versions from the same Wish.

For MVP:
- Regeneration creates a new generation record.
- Previous successful results remain accessible.
- Users can generate with the same settings or adjust personalization inputs.

Do not overwrite previous results.

# 7. AI Personalization & Content Engine

## 7.1 Design Principle

Manifest should provide personalized results rather than simply inserting the user's wish into a generic prompt.

The AI pipeline should translate the wish into several layers:

**Wish → Intent → Emotional Context → Creative Concept → Generation Prompt → Final Media**

Example:

Input:

"I want to find true love and build a happy relationship."

AI interpretation:

- Intent: Love and connection.
- Emotional context: Security, tenderness, belonging, joy.
- Creative concept: A warm romantic moment in a beautiful European city.
- Visual direction: Cinematic, soft golden light, intimate atmosphere.
- Affirmation: "I am worthy of a love that feels safe, genuine, and beautiful."

## 7.2 Personalization Quality

The generated content should consider:

- The actual meaning of the wish.
- Specific details provided by the user.
- Desired emotional experience.
- Visual consistency.
- Appropriate affirmation language.
- Chosen output format.

Avoid:
- Generic motivational imagery.
- Repetitive visual concepts.
- Inconsistent aesthetics.
- Unnatural AI-generated text.
- Excessive or unrealistic promises.

## 7.3 Generation Architecture

The AI production engine should be modular.

Suggested internal components:

- Wish Interpreter
- Creative Director / Concept Generator
- Prompt Builder
- Image Generation Adapter
- Video Generation Adapter
- Audio Generation Adapter
- Media Composer
- Quality Checker

Different AI providers should be replaceable without rewriting the product's core business logic.

## 7.4 Asynchronous Generation

Video and audio generation may take time.

Generation must run asynchronously.

Recommended workflow:

Frontend → Backend API → Generation Job → External AI Provider → Callback / Polling → Media Storage → Database Update → Frontend Result

Never depend on a single long-running HTTP request to generate a video.

# 8. Monetization Strategy

**MVP: Prepare the architecture, but avoid overbuilding payment infrastructure before validating user engagement.**

## 8.1 Proposed Business Model

Two possible monetization mechanisms:

**A. Subscription**

Monthly or yearly membership.

Potential benefits:
- Monthly generation quota.
- Access to all supported output formats.
- Higher generation limits.
- Priority generation.
- Daily Manifest subscription.

**B. Star Coins / Credits**

Users purchase additional credits to generate more content.

Credits may be consumed according to output type and generation cost.

Video generation may cost more credits than image or audio generation.

## 8.2 Suggested MVP Approach

- Provide a limited free generation quota.
- Keep usage limits configurable on the backend.
- Prepare a credit-based usage model.
- Do not hardcode generation limits into frontend logic.
- Defer complex payment integration until generation cost and user demand are better understood.

The first release can operate with controlled free quotas or invite-only access.

# 9. Daily Manifest — Future Phase

**Priority: P1**

Daily Manifest is a future retention feature.

It allows users to receive daily manifestation content based on their wishes.

Potential experience:
- Select a Wish to follow.
- Receive a daily affirmation.
- Receive a personalized or relevant image, video, or audio.
- Email delivery.
- Configure delivery time and timezone.

MVP does not need to build a complete daily delivery system.

However, the Wish data model should be designed to support future subscriptions and notification preferences.

Important: Daily Manifest should not require generating a brand-new video for every user every day. Generation frequency and delivery strategy should be optimized according to actual costs and user engagement.

## 11.2 Architecture Principles

- Frontend handles user interactions and media presentation.
- Supabase handles authentication and application data.
- Cloudflare Workers handles privileged API requests, generation orchestration, callbacks, and scheduled tasks.
- External AI providers handle image, video, and audio generation.
- Cloudflare R2 stores generated media.
- Supabase stores metadata, ownership, generation status, and relationships.

Do not perform heavy video rendering inside Cloudflare Workers.

Generation should use asynchronous external jobs and callbacks or polling.

# 13. Security, Privacy & Responsible AI

This product handles highly personal wishes and may eventually handle personal photos and voice inputs.

Requirements:

- Users can only access their own wishes and generations.
- Use Supabase Row Level Security.
- Keep AI provider API keys and other secrets on the server.
- Never expose private storage credentials.
- Validate uploaded files.
- Restrict upload size and file types.
- Provide account deletion and data deletion.
- Explain how uploaded reference photos are used.
- Do not use private user content for public promotion without explicit permission.
- Do not imply that generated content guarantees real-world outcomes.
- Provide safeguards against harmful, exploitative, or deceptive generation requests.

Generated content should be framed as visualization, inspiration, and personal reflection — not factual predictions or guaranteed manifestations.

# 18. Key Product Decisions to Validate

These are the main decisions to settle during implementation planning:

**1. Personalization depth**

Should the user be able to upload a selfie or reference photo to generate content featuring themselves?

Recommendation: Support optional reference images, but do not make them mandatory for the initial experience.

**2. Generation format selection**

Should the user choose Video / Image / Audio directly, or should the system recommend a format based on their wish?

Recommendation: Let the user choose. Default to Video because it provides the most immersive manifestation experience, while Image and Audio offer lower-cost alternatives.

**3. Generation cost and free quota**

What is the real cost of generating a video, image, and audio asset?

Recommendation: Establish real provider costs and failure rates before setting final credit prices. Keep quota and pricing configurable.

**4. Generation quality**

How do we define a successful manifestation result?

Recommendation: Evaluate on four dimensions:
- Wish relevance
- Visual quality
- Emotional resonance
- Personalization accuracy

**5. First-launch content quality**

The first user experience should demonstrate what makes Manifest special.

Recommendation: Prepare a small number of excellent example manifestations for the landing page and social media. These examples should demonstrate the quality ceiling of the product, while actual user generations remain personalized.

# 19. Final MVP Definition

Manifest MVP is a wish-centric, AI-powered personal experience.

Its essential loop is:

**Create a Wish → Visualize It → Experience It → Save It → Return to It.**

The first release does not need a large content library, a complex social system, or a sophisticated subscription ecosystem.

It needs to do one thing exceptionally well:

**Help users turn something they deeply wish for into a beautiful, personal experience they want to revisit.**

The quality of this experience — not the number of features — should determine the success of the MVP.
